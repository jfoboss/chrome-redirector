# Site Redirect Rules — перенаправления сайтов

[![License](https://img.shields.io/github/license/jfoboss/chrome-redirector)](LICENSE)

Расширение Chrome со своим списком перенаправлений: открываете адрес, и браузер сразу переходит на нужную страницу.

| Откуда                        | Куда                                |
| ----------------------------- | ----------------------------------- |
| `https://example.com/`        | `https://example.com/console`       |
| `https://example.com/welcome` | `https://example.com/console`       |
| `https://example.org/`        | `https://app.example.org/dashboard` |

Интерфейс на русском и английском (по языку браузера).

## Зачем это нужно

Многие рабочие сервисы встречают на главной странице одинаково всех: и того, кто пришёл впервые, и того, кто работает в сервисе каждый день. Облачные консоли, трекеры, CI, системы мониторинга, внутренние порталы — на корне домена продающий лендинг, а работа начинается на кнопке «Войти», «Консоль» или «Dashboard».

Для нового посетителя это правильно. Для инженера, который открывает сервис десять раз за день, это лишняя страница и лишний клик на каждом заходе. Путь каждый раз один и тот же: набрать адрес или выбрать его из подсказок адресной строки, дождаться лендинга, нажать кнопку, дождаться нужной страницы.

Некоторые сервисы решают это сами: GitHub показывает залогиненному пользователю дашборд, а не маркетинговую страницу. Многие — нет, и у владельцев сайта могут быть на то свои причины: главная для них — маркетинговый канал, и это их право. Расширение решает вопрос на вашей стороне: вы сами указываете, куда вас вести, и это никак не влияет на сайт и на других его посетителей.

## Как помогает в работе

- **Сразу к работе.** Адрес, который вы набираете по привычке, ведёт туда, где вы работаете: в консоль, на доску задач, на нужный дашборд.
- **Ловит все входы.** Закладка помогает, только если открывать сервис через неё. Правило срабатывает при любом способе: ввод адреса, подсказка адресной строки, ссылка из чата или письма.
- **Работает с цепочками.** Если сайт сам перенаправляет `/` на `/welcome`, правило для `/welcome` тоже сработает.
- **Не отрезает лендинг.** Правило типа «Точный адрес» срабатывает только на указанной странице — остальные страницы сайта (тарифы, документация, новости) открываются как обычно. Любое правило можно выключить флажком, а все сразу — общим переключателем.
- **Одни правила на всех компьютерах.** Список правил синхронизируется между вашими браузерами Chrome. Доступ к сайтам Chrome выдаёт на каждом компьютере отдельно: на новом компьютере значок покажет «!» — откройте список правил и нажмите «Сохранить».
- **Можно поделиться с командой.** Список правил экспортируется в JSON и импортируется обратно — удобно раздать коллегам набор для общих рабочих сервисов. Импортированные правила добавляются к вашим и начинают работать после «Сохранить». Если такой адрес у вас уже есть, расширение покажет совпадения и спросит, какие правила заменить; точные копии пропускаются.
- **Ничего не видит.** Перенаправление выполняет сам Chrome; расширение не видит историю и содержимое страниц (подробнее — в разделе «Приватность»).

## Примеры

| Ситуация | Откуда | Куда | Тип правила |
| --- | --- | --- | --- |
| Облачная платформа показывает лендинг, консоль — на соседнем пути | `https://cloud.example.com/` | `https://cloud.example.com/console` | Точный адрес |
| Сайт сам уводит с главной на страницу приветствия | `https://cloud.example.com/welcome` | `https://cloud.example.com/console` | Точный адрес |
| Маркетинг на одном домене, приложение — на другом | `https://example.org/` | `https://app.example.org/dashboard` | Точный адрес |
| Вики открывается на общей главной, а нужно пространство команды | `https://wiki.example.com/` | `https://wiki.example.com/spaces/TEAM` | Точный адрес |
| Сервис переехал: любая страница старого адреса ведёт на главную нового | `https://old-portal.example.com/` | `https://portal.example.com/` | Весь сайт |
| Сервис переехал, старые ссылки должны вести на те же страницы | `^https://old-portal\.example\.com/(.*)` | `https://portal.example.com/\1` | Регулярное выражение |
| Документация открывается на последней версии, а вы работаете с конкретной | `^https://docs\.example\.com/latest/(.*)` | `https://docs.example.com/v2/\1` | Регулярное выражение |

## Приватность

- Расширение построено на `declarativeNetRequest` (Manifest V3): Chrome сам сравнивает адреса с правилами и выполняет перенаправление. Расширение не получает историю, адреса открытых страниц и их содержимое. Единственное исключение — когда вы сами нажимаете на значок расширения, оно узнаёт адрес текущей вкладки, чтобы предложить правило для неё.
- Доступ запрашивается только к сайтам из колонки «Откуда» и отзывается, когда правил для сайта больше нет. Исключение — правила с регулярными выражениями: им нужен доступ ко всем сайтам.
- Правила хранятся в `chrome.storage.sync` вашего браузера. Если в Chrome включена синхронизация, они синхронизируются через ваш аккаунт Google штатными средствами Chrome. Разработчику расширения ничего не отправляется.

[Политика конфиденциальности](store/PRIVACY.md).

## Установка

- **Из Chrome Web Store** — откройте [страницу расширения](https://chromewebstore.google.com/detail/ibkaigdgfdnicobpfdfgjnpnebghbhhb) и нажмите «Установить».
  Собирать ничего не нужно, обновления приходят автоматически.
- **Без магазина** — скачайте ZIP из [последнего релиза](https://github.com/jfoboss/chrome-redirector/releases/latest), распакуйте и загрузите папку, как описано ниже. Обновлять придётся вручную.
- **Для разработки:** `chrome://extensions` → включить «Режим разработчика» →
  «Загрузить распакованное расширение» → выбрать папку `extension/`.

## Использование

- Значок расширения → **Перенаправлять этот адрес…** — открывает список правил с новой строкой: в «Откуда» уже подставлен адрес текущей страницы (без параметров после `?`). Впишите «Куда» и нажмите «Сохранить».
- Значок → **Все правила** — список: порядок, вкл/выкл, импорт/экспорт в JSON.
- При сохранении расширение сначала покажет, к каким сайтам и зачем нужен доступ, а затем Chrome спросит разрешение «Читать и изменять данные на сайтах» — так Chrome называет любой доступ к сайту. Без него
  перенаправление не сработает. Доступ к сайтам, для которых правил больше нет, отзывается сам.
- Значок показывает состояние: число — сколько правил работает; **!** — у части правил нет доступа к сайту (откройте список и нажмите «Сохранить»); **off** — перенаправления выключены; **err** — Chrome не принял правила (подробности во всплывающей подсказке значка).

Типы правил:

- **Точный адрес** — тот же домен и путь; слэш в конце и параметры `?…` не важны, http и https считаются одинаковыми.
- **Весь сайт** — любая страница домена.
- **Начинается с** — адрес начинается с указанного. Сравнивается как текст: правило для `https://example.com/docs` поймает и `/docs-old`; чтобы ограничиться разделом, добавьте слэш: `/docs/`.
- **Регулярное выражение** — RE2, в «Куда» можно использовать `\1`, `\2`…
  Требует доступа ко всем сайтам.

Домен сравнивается точно: `example.com` и `www.example.com` — разные адреса, поддомены тоже не учитываются. Если сайт открывается под обоими именами, сделайте два правила.

Если сайт сам перенаправляет (например, `/` → `/welcome`), правило для `/welcome` тоже
сработает: перенаправление выполняется для каждого запроса в цепочке. Правило, которое
перенаправляет само на себя, сохранить нельзя.

## Ограничения

- **Около 100 КБ на все правила** — лимит синхронизации Chrome. Это примерно 600–700 правил с обычными адресами.
- **Не больше 1000 включённых правил** — лимит Chrome на число правил в расширении.
- **Одно правило — не больше ~7 КБ** («Откуда» и «Куда» вместе).

Если лимит превышен, расширение не сохранит список и скажет, что именно не так; уже сохранённые правила продолжат работать.

## Разработка

```sh
npm install                      # зависимости для скриптов (Playwright)
npm test                         # модульные тесты
npm run build                    # ZIP для Chrome Web Store → dist/ (нужна утилита zip)
npx playwright install chromium  # один раз, для следующей команды
npm run store-images             # скриншоты и промо-картинка для магазина → store/images/
python3 scripts/make-icons.py    # перерисовать иконки
```

Строки интерфейса — в `extension/_locales/{ru,en}/messages.json`.

## Версионирование и релизы

Версии по [SemVer](https://semver.org/lang/ru/), релизы делает [release-please](https://github.com/googleapis/release-please) по [Conventional Commits](https://www.conventionalcommits.org/ru/):

| Заголовок PR / коммит | Что будет с версией |
|---|---|
| `fix: …` | patch: 1.3.0 → 1.3.1 |
| `feat: …` | minor: 1.3.0 → 1.4.0 |
| `feat!: …` или `BREAKING CHANGE:` в теле | major: 1.3.0 → 2.0.0 |
| `docs:`, `ci:`, `chore:`, `refactor:`, `test:` | релиза не будет |

Как это работает:

1. PR мёржится в `main`. CI проверяет, что заголовок PR в формате Conventional Commits (при squash merge он станет сообщением коммита).
2. `release.yml` держит открытым PR `chore(main): release X.Y.Z`: поднимает версию в `extension/manifest.json` и `version.txt`, дописывает [`CHANGELOG.md`](CHANGELOG.md). Новые коммиты в `main` обновляют этот PR.
3. Мёрж release PR = релиз: тег `vX.Y.Z`, [GitHub Release](https://github.com/jfoboss/chrome-redirector/releases) с changelog и приложенным ZIP.
4. ZIP из релиза загружается в Chrome Web Store вручную — см. [`store/PUBLISHING.md`](store/PUBLISHING.md).

Версию вручную не править. Нужна конкретная — пустой коммит с `Release-As: X.Y.Z` в теле.
